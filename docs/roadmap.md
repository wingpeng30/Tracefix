# TraceFix 路线图

TraceFix 的目标是在固定模型和预算下，通过代码检索、上下文管理和测试反馈，减少真实 Issue
修复的输入 Token 与耗时，同时维持或提高独立验收成功率。

| 阶段 | 状态 | 验收门槛 | 证据与下一步 |
| --- | --- | --- | --- |
| Agent 核心、工具与轨迹 | 已完成 | 合成任务闭环、预算与轨迹可追溯 | V0.1–V0.3 开发记录 |
| 上下文压缩、行动效率、Repo Map | 已完成基础实现 | 可关闭模块、离线检索对照 | 12 题 Repo Map Hit@5 75%，MRR 0.465 |
| 真实候选与固定源码 | 已完成 | 12/12 commit、工件、组合补丁预检通过 | `benchmarks/real_candidates/` |
| 可信行为验收 | 已完成复验 | 12 题逐题保留构建、收集、运行证据；7 题合格 | V0.8.3；可准备付费实验配置 |
| 真实 Token 对照 | 未开始 | 每题 C/T 各至少三次；独立验收、Token、耗时和费用完整 | 仅对通过行为资格的任务执行 |
| 最终评测与对照 | 未开始 | 数十题、留出集、消融；必要时与 mini-swe-agent 同条件比较 | 简历只引用此阶段实测数字 |

V0.8.3 完成 12 道候选的可审计复验：7 题满足相同 node ID 下 base 断言失败、gold 通过的资格
规则。下一步是在这 7 题上预注册真实 C/T 实验配置；Sphinx 10323/10435 仍需 Linux 验证，
Pylint 4551/4604 和 Requests 1724 保留为不合格的失败类别样本。

长期功能由失败证据决定：早期事实丢失时改进证据摘要；无效搜索时改进检索排序和读取记忆；
独立验收失败时增加补丁验证；环境差异反复出现时加入容器化。
