# TraceFix 基础安全规范

安全策略版本：`tracefix-basic-1`。这是面向个人项目的固定防护基线，不是完整的提示注入防御或多租户安全承诺。

## 信任边界

用户任务是授权范围的来源。仓库源码、测试输出、Repo Map、Skill、历史记忆、工具返回值和压缩摘要均视为不可信数据；它们不能改变系统规则、扩大文件范围、授权访问凭据或要求执行任意命令。模型只能通过 TraceFix 暴露的固定工具接口行动。

普通新任务默认在预先准备的 `ordinary` Docker 镜像中运行。每次任务新建容器，容器不联网、不挂载宿主仓库或 Docker socket，以非 root UID 10001 执行，根文件系统只读并受 CPU、内存和进程数限制。当前 TraceFix 执行器在任务代码启动前由宿主复制到 root 所有的容器目录，文件与目录设为只读；容器会核对执行器哈希和 UID 10001 的写入拒绝结果。镜像必须由用户预先准备，运行不会自动拉取或构建，也不会在 Docker 不可用时回退到本地。

Docker 提供进程和文件系统隔离，但共享宿主内核及 Docker daemon；本规范不声称能抵御容器运行时或内核漏洞。显式选择 `execution_backend = "local"` 时，任务测试代码在当前用户权限下执行，只适用于受信任仓库。仅本地支持的技能、记忆、连续对话、MCP 和结束前回归目标仍按各自配置限制；不支持的组合会报错，不会自动转换后端。

## 文件与补丁

工具访问只允许任务工作区内的相对路径，并同时检查输入路径和解析后的真实目标。拒绝越界路径、符号链接逃逸、Git 元数据、真实 `.env` 文件及其常见变体、凭据目录和 TraceFix 内部保护目录；公开模板 `.env.example` 可读。Read、Search、Patch、Repo Map、Diff 和 Serena MCP 快照共用该边界。直接访问越界文件返回错误，批量扫描跳过受保护文件；Diff 和 MCP 先过滤路径再读取正文。补丁仍需上下文唯一匹配和 `git apply --check`，导出只生成补丁，不会应用回原仓库。

该名单用于防止常见凭据误读，不能替代仓库清理或秘密管理。不要把真实密钥放入源码、测试输出或任务描述；`.env` 只用于宿主侧模型配置，不会作为容器测试变量传入。明确配置的项目环境变量会校验并注入测试或构建子进程，凭据变量、`PYTEST_*` 和 TraceFix/Python 控制变量会被拒绝。

## 测试与子进程

`run_tests.command` 保留 pytest 语法入口，但内部只允许 pytest 选项白名单和仓库内测试目标。插件加载、配置覆盖、任意日志/报告路径、未知参数、紧贴写法绕过和越界目标会在进程启动、测试计次之前拒绝。TraceFix 自己管理 pytest 配置、审计插件、报告文件和固定 `.tracefix-test-tmp`。

测试、构建、源码导入探针只继承最小操作系统环境；项目变量必须通过现有显式配置提供。临时目录、Python 导入路径和审计变量由 harness 设置。容器测试仍能导入并执行任务代码，因此允许列表和沙箱共同降低误操作风险，但不使仓库代码变为可信。

## 失败与证据

缺少 Docker、镜像、测试目标或源码导入配置时，在构造模型客户端前停止；不会自动下载镜像、安装依赖或切换到本地。执行器初始化、身份检查或写保护探针失败时停止运行。恢复只接受原有实现身份校验；旧检查点不绕过校验自动迁移。容器清理失败保留标签和容器 ID，要求检查后处理。

测试通过只证明列出的公开目标在当前运行中通过，不证明补丁没有危险行为、没有隐藏副作用或不存在安全漏洞。提示注入仍可能影响模型判断；文件边界、参数白名单、最小环境和 Docker 隔离提供的是纵深防御。实际安全能力以本次实现和明确记录的验证范围为准。
