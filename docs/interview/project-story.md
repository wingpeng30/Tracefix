# 项目历程与技术决策

## 一句话介绍

TraceFix 是面向 Python 仓库缺陷修复的单 Agent 工程框架：让模型在受控工具、隔离源码、
预算账本和可核验测试证据下完成定位、修改、验证、导出补丁，而不是只生成看似正确的代码。

## 做了什么、为什么、结果

| 阶段 | 实际工作 | 为什么需要 | 结果与边界 |
| --- | --- | --- | --- |
| 基本闭环 | 强类型消息与工具调用、LiteLLM 适配、搜索/读取/修改/测试/Diff 工具、JSONL 轨迹 | 模型输出不能直接当作可靠修复；每次工具执行需要可检查 | 建立可运行本地闭环；早期合成任务仅证明控制流 |
| 仓库定位 | Python AST 索引、仓库图和任务相关 Repo Map | 大仓库无法一次读完，需要先缩小候选文件和符号范围 | 提供确定性定位入口；离线检索指标不能直接替代真实修复率 |
| 上下文与费用 | 工具输出裁剪、历史折叠、预算发送前预留、未知用量停止、请求视图身份 | 长轨迹会挤占上下文；缺失 usage 或中断不能按零费用处理 | 真实运行验证预算停止与压缩；重复读取也可能是在补取此前不可见证据 |
| 验收可信度 | 独立干净源码验收、隐藏目标与公开回归分开、源码导入身份、补丁保护集 | Agent 测试通过、正常结束和独立补丁正确是不同信号 | 冻结公开任务资格；发现并保留网络、平台和临时文件污染问题 |
| 普通用户路径 | 安装包 CLI、doctor/inspect/resume/verify/report/export、本地任务事实与检查点 | 框架需要在普通仓库中可使用、可解释、可恢复 | 有安装包零调用闭环和 HTML 演示；恢复只接受满足身份与确定边界的记录 |
| 可选增强 | 默认关闭的 Skills、只读 Serena MCP、Docker 独立执行/重建恢复、经验记忆与连续对话 | 扩充能力时需要控制权限、环境身份和生命周期 | 有离线/真实进程/容器及 CI 证据；未证明这些增强提高真实模型成功率 |
| 真实对照 | 冻结任务、平衡排程、独立验收、完整失败分母、任务级 bootstrap、费用/耗时分列 | 防止挑题、重抽、把录制响应成功当模型能力 | 90 次及 20 次实测完成；观察到的差异不足以证明稳定能力提升 |

## 最值得讲的取舍

- 完整历史与模型实际看到的请求视图分开保存。压缩改变视图，不篡改历史；不能机械去重读取。
- Agent 内部测试用于反馈，外部独立验收用于判定。最终答复完成并不等于补丁通过。
- 预算保护先预留后发送。未知费用保留预留并停止，不能自动重发以掩盖中断。
- 源码、环境、实现、协议和补丁分别记录身份。CI 通过必须对应精确提交，不能借用别的版本。
- Skills/MCP/记忆等增强默认关闭。机制能工作与机制有模型收益分别验收。
- 效果不确定时如实报告，包括失败、污染、区间跨零和没有采用的候选策略。

## 典型踩坑

1. 缺失 usage 回退为零会错误释放预算，改成明确格式错误及停止后续请求。
2. 固定过多失败测试批次导致压缩没有真正释放上下文，改成固定最新必要证据并实测触发。
3. 独立验收被网络、旧 Python 兼容性或源码导入位置影响，先验证任务资格再比较模型。
4. B 的补丁收集遗漏动态登记的测试临时目录，导致 Click/Sphinx 污染；原失败保留，修复供后续使用。
5. Windows PID 可复用，不能用 PID 必须互异证明新进程；改用进程启动、退出与轮次收据。
6. HTTP 保活可能使普通超时不是硬墙钟截止；新增独立请求进程与父进程回收，但新协议未付费验收。
