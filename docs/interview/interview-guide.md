# 面试问答与演示

## 两分钟介绍

我做的是一个 Python 仓库 Coding Agent 的工程闭环。模型先用仓库索引和 Repo Map 定位，
再通过受控工具读取、修改和测试；最终补丁要在另一份干净源码中独立验证。
系统同时保存完整轨迹、模型实际请求视图、费用账本、代码和环境身份，方便解释失败和恢复。

项目最有价值的部分是把“模型说完成”“测试通过”“独立补丁正确”分开，以及处理预算、
环境、源码导入和恢复中的真实故障。我也做过固定任务对照：90 次实验中 TraceFix 补丁通过
6/30，最简循环 2/30，但统计区间跨零；扩大额度后两组各 6/10。我不会把这些结果包装成
已经证明稳定领先，尤其第二批发现了评测补丁污染。

## 常见追问

| 问题 | 回答要点 |
| --- | --- |
| 与直接调用模型的区别？ | 有工具反馈、仓库定位、独立源码和验收、预算与状态恢复、可追溯证据 |
| 为什么不是多 Agent？ | 先把单 Agent 的权限、环境和验收做可信；复杂编排不是当前效果证据 |
| 怎么防止改测试作弊？ | 受保护测试/配置、产品补丁收集、干净源码独立目标与回归、实际导入身份 |
| 如何处理上下文太长？ | 完整历史不丢，模型视图裁剪与折叠；固定最新必要测试/补丁和任务事实 |
| 预算为什么提前停止？ | 使用发送前保守输入和输出预留，实际 usage 尚未达到阈值也可能不能准入下一请求 |
| 中断如何恢复？ | 只接受确定完成的工具边界，核验模型/工具/源码/环境；未知费用不重发 |
| 如何评价真实效果？ | 固定协议、平衡排程、所有失败留在分母，任务级配对 bootstrap，成本和时间分别报告 |
| 最重要的负结果？ | 重复 no_effect 后重读没有达到采纳门槛；C/B 成功率优势未得到稳定证据 |
| 为什么留原始失败？ | 后续修复不能回写原实验；污染和基础设施限制影响结论可信度 |
| 记忆、Skills、MCP 是否有效？ | 有机制与工程证据，模型成功率收益尚未测，不能混用结论 |

## 离线演示

保留的现成报告：`D:\Tracefix\portfolio-demo-skills-2\report.html`。
先展示测试失败、搜索与读取、一个小补丁和复测，再解释这是脚本模型控制流演示。
新输出目录必须不存在：

```powershell
.\.venv\Scripts\tracefix-reproduce.exe --scenario pagination --skills-enabled --output runs/interview-demo-new
.\.venv\Scripts\tracefix.exe report --run runs/interview-demo-new --output runs/interview-demo-new/report.html
```

该入口禁止供应商构造和请求，费用不是实际模型费用。准备面试不必现场调用付费模型。
也可演示 `regression-feedback` 场景，展示首次修改引入回归、反馈后修正和独立验证。

## 简历表述

可写：实现单 Agent 缺陷修复框架、AST 仓库定位、上下文与费用保护、独立补丁验收、
检查点恢复和离线 HTML 报告；构建冻结任务资格与对照评测，保留可核验失败证据。

不能写：已证明稳定提高真实成功率、长期记忆提高能力、所有任务端到端完成、
节约了确定比例的实际供应商账单费用，或把脚本响应验收说成模型自主效果。
