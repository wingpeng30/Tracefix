# V0.6.1：Agent 行动收敛与只读工具记忆

## 背景

V0.6.0 的真实 Repo Map 单次预筛选中，Repo Map 把首次读取目标文件的平均步骤从 2.00 提前到
1.33，但 6 个 trial 全部因累计输入 Token 超过 80k 而中断。各 trial 的单次上下文最高只有
约 10k～13k，所以问题不是 32k 历史折叠失效，而是 Agent 每轮重发历史、定位后仍继续搜索和
阅读，没有及时进入补丁与测试闭环。

## 本次实现

### 阶段状态

新增 `AgentPhase`：`EXPLORE`、`PATCH`、`VERIFY`、`FINISH`。阶段由确定性工具事实驱动：

- 读取足够的 Repo Map 高排名候选，或探索达到软上限：进入 `PATCH`；
- 成功应用补丁：进入 `VERIFY`；
- 测试失败：回到 `PATCH`；
- 测试通过且 Diff 非空，或模型给出最终回答：进入 `FINISH`。

阶段变化写入 `agent_phase_changed` 事件，不保存模型隐藏推理。

### Repo Map 行动提示

Repo Map 现在按序号展示候选，并说明候选来自任务模块、符号、路径、综合关键词或图邻居。提示明确
要求首轮先读取 Top-2，只有这些文件不足以解释问题时才做针对具体符号的搜索；定位后应进入最小补丁
和相关测试。

### 搜索与读取记忆

成功的 `search_code` 和 `read_file` 以规范化参数签名缓存。完全相同的重复调用不会再次执行工具，
而是返回包含原调用 ID、文件或匹配摘要的紧凑结果；完整原始结果仍保留在消息历史和轨迹中。成功应用
补丁后缓存全部失效，避免把已经变化的源码误报为未改变。

### 探索软预算与累计 Token 提示

新增默认配置：

- `max_exploration_steps=4`
- `max_search_calls=4`
- `max_file_reads_before_patch=8`
- `repo_map_reads_before_patch=2`

达到软上限不会强制拒绝工具，而是要求停止一般搜索、形成最小补丁；确有缺失信息时仍允许一次明确的
定向读取。累计输入 Token 达到 50%、70%、85% 时分别追加一次收敛提示，85% 时只优先补丁、测试、
Diff 或最终回答；若模型仍请求搜索或读取，系统会返回短小的策略拒绝结果而不实际执行。CLI 和对应
`TRACEFIX_*` 环境变量可覆盖这些值。

### 搜索结果降噪

`search_code` 默认结果上限从 50 降至 20；每个文件最多返回 5 条命中；源码路径先于测试、文档和
示例。显式传入 `max_results` 的兼容范围仍为 1～200。

## 新增评测指标

真实轨迹分析新增：

- `first_patch_step`
- `first_test_step`
- `post_target_search_calls`
- `cached_tool_calls`
- `phase_transitions`

其中标准目标文件只在 Agent 结束后的评测端使用，不进入模型上下文。

## 自动化验收

相关模块共 99 项测试通过；全量验收为 188 项通过，核心覆盖率 91.31%。测试覆盖阶段转换、重复
读取缓存、探索软上限、累计 Token 提示、搜索单文件限流、Repo Map 提示、Runner 和真实任务验收。
Ruff 与 compileall 通过。Windows 上既有的 `.pytest_cache` 权限警告不影响测试结果。

## 实验状态与下一步

本阶段没有调用真实 LLM，因此没有新的成功率、Token 或费用结果，也不会把脚本化 LLM 测试解释为
性能提升。下一步应在与 V0.6.0 完全相同的三个固定任务上重新执行一次 Repo Map 开关预筛选，比较
首次补丁、首次测试、目标文件后搜索次数、正常结束率、隐藏验收和累计 Token；有至少一组形成完整
闭环后，才考虑每题每组 3 次的正式实验。
