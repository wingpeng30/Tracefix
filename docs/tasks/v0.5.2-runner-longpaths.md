# V0.5.2：补齐 Runner 与工具层 Windows 长路径

## 问题

V0.5.1 修复了任务工件换行哈希，并为任务准备器与真实实验器的 Git 命令开启长路径。第二次
GitHub Actions 将失败从三项降到一项，但配对实验的六个 trial 全部得到
`agent_completed=false`。原因是流程中还有两层 Git 操作：

1. `TraceFixRunner` 会从准备好的任务源仓库再次 clone 独立 Agent 工作区。
2. Agent 的 `apply_patch`、`get_git_diff` 和工具注册会继续调用 Git。

这些命令位于更深的运行目录，仍可能超过 Windows 传统路径限制。

## 实际改动

- `TraceFixRunner._run_git()` 统一添加命令级 `-c core.longpaths=true`。
- 工具工作区校验、Git patch 预检/应用以及最终 diff 命令使用同一配置。
- 配置只影响当前 Git 子进程，不修改宿主机全局配置。
- V0.5.1 与 V0.5.0 标签保持不可变，本次修复发布为 V0.5.2。

## 验收与实验边界

本地重点回归覆盖 Runner、五个工具和配对实验，共 `45 passed`；完整验收为
`168 passed`、覆盖率 `90.74%`，且 Ruff、compileall、`git diff --check` 均通过。

发布后 GitHub Actions Run #7 在 Windows 的 Python 3.11 与 3.12 矩阵均成功，运行时长
3 分 10 秒：<https://github.com/wingpeng30/Tracefix/actions/runs/34427389544>。
工作流仍有 `actions/checkout@v4` 与 `actions/setup-python@v5` 的 Node.js 20 弃用警告；
这不是测试失败，也不影响本轮发布功能，后续可单独升级工作流 action。

本次没有调用真实 LLM，没有新增 Token 或人民币费用；V0.5.0 的 32k 预筛选结论保持不变。
