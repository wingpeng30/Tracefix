# V0.8.4：严格真实任务验收

本轮先修复验收可信度，再重验固定的 SWE-bench Verified 候选；没有调用 LLM，也没有产生模型费用。

## 实际改动

- 验收器只接受结构化执行 node ID，不再以 JUnit 测试数量代替实际执行集合；节点路径保留完整目录和参数化标识。
- pytest 子进程移除继承的 `PYTEST_ADDOPTS` 与自动加载的第三方插件，但保留被测仓库自己的 pytest 配置和必要插件。
- 审计记录增加收集异常的类型、模块和符号，以及当前 checkout 内实际导入模块路径；日志在落盘前脱敏已知模型密钥。
- `EnvironmentRecipe` 增加精确的 `expected_base_failure`。只有审核过的 collection `ImportError` 能作为独立资格类型，gold 仍须完整收集并通过。
- 环境 marker 现在包含实际依赖指纹；依赖漂移时拒绝复用。环境创建、ensurepip 与 pip 使用 TraceFix 管理的临时目录，避免系统 Temp ACL 干扰。固定源码的安装改在环境临时副本中完成。
- `validate-real-behavior --test-python` 支持单题复用已有、经配方版本校验的解释器，避免为相同 Python/依赖组合重复创建大型环境。

## 配方修正

Pylint-4551 的官方参数化 node ID 被截断，改为最小函数级选择器；4551 与 4604 的 base 都精确匹配测试补丁导入的 gold 新增符号。Sphinx-10435 已取消错误的 Linux-only 判断，在 Windows 上补齐 `html5lib==1.1` 与 `Pygments==2.11.2` 后完成验证。pytest 三题固定 `pytest==7.1.2`，并通过上游 `setup.py --version` 仅在隔离副本生成版本文件，避免把任务源码安装进共享环境。

## 边界

Requests-1724 是 Python 2.7 行为，在现有 Python 3.9 环境中 base 已通过，继续标为“业务差异未复现”。Sphinx-10323 保留上游 Windows xfail，待 Linux 验证；本轮不安装 WSL、Docker 或旧 Python。

完整 base/gold 日志和逐题 JSON 位于被 Git 忽略的 `runs/real-candidate-behavior-validation-v084-*`。

## 验证结果与限制

`tests/test_real_experiment.py` 与 `tests/test_real_environment.py` 的 17 项回归通过；Ruff 与
`compileall` 通过。全量 `pytest --cov=tracefix` 在 209 项中运行至 `test_benchmark.py` 后再次留下
未退出的 Windows 子进程，已保留命令与部分输出并停止该子进程，故本轮不声称新的全量覆盖率结果。
这与 V0.8.3 已记录的会话级 pytest 停滞现象一致，后续应独立处理测试进程生命周期，而不是将其
误归因为业务验收失败。
