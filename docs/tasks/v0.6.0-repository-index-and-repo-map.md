# V0.6.0：Python Repository Indexer 与 Repo Map

## 本次完成内容

V0.6.0 在现有单 Agent Loop 前加入确定性的静态定位层。`RepositoryIndexer` 只扫描隔离工作区内的 Python 文件，使用标准库 `ast` 提取类、函数、方法、导入和保守的调用名称；不会调用 LLM，也不读取 `.git`、虚拟环境、缓存、构建目录或超大文件。

每次 `tracefix run` 在克隆完成后生成任务相关的 `RepoMap`：候选源码文件、符号及行号、导入邻居和相关测试候选。地图作为第二条 system 消息进入模型请求，模型仍必须用 `read_file` 和测试确认事实。完整索引不会代替代码阅读，也不宣称构建了精确调用图。

运行产物新增 `repo-map.json`；`result.json` 引用其路径和结构化摘要，JSONL 新增 `repository_indexed` 与 `repo_map_added` 事件。启用 `--record-request-views` 时，地图会随实际模型请求视图一起保留，便于分析“索引给出什么、模型实际看到什么”。

## 配置与对照

默认启用。可使用 `--no-repo-map` 或 `TRACEFIX_REPO_MAP_ENABLED=false` 构造定位层对照，`--repo-map-max-chars` / `TRACEFIX_REPO_MAP_MAX_CHARS` 可约束地图大小。该开关与上下文压缩独立，不能把 Repo Map 带来的输入变化归因于压缩。

## 本轮验证与非目标

新增单元测试覆盖符号/导入提取、坏语法文件降级、目录跳过、字符上限、确定性输出、Agent 请求注入、轨迹事件、Runner 产物和 CLI 覆盖。定向回归（本模块、Runner、CLI）为 26 passed；`ruff check .` 与 `python -m compileall -q src tests` 均通过。没有运行真实 DeepSeek API。后续新增的零成本定位评测结果见 [`../experiments/v0.6.0-repo-map-retrieval-eval.md`](../experiments/v0.6.0-repo-map-retrieval-eval.md)。
