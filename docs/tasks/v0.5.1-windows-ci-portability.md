# V0.5.1：Windows CI 可移植性修复

## 任务背景

V0.5.0 在开发机完成 155 项自动化测试，但推送后的 GitHub Actions 在 Python 3.11 和 3.12
上同时失败。失败来自运行环境差异，不是 Agent 或真实 Issue 实验逻辑变化：

1. GitHub Windows Runner 检出文本时可能执行 LF/CRLF 转换，原先按原始字节计算的任务
   SHA-256 因而与清单不一致。
2. CI 中 `pytest` 临时目录、配对实验目录和任务目录多层嵌套，Git 写对象或检出文件时可能
   超过传统 Windows 路径长度限制。

## 实际改动

- 真实任务的 `problem.md`、`gold.patch` 和 `test.patch` 改用规范化文本哈希：UTF-8 解码后
  将 CRLF 和单独 CR 统一为 LF，再计算 SHA-256。
- 哈希仍对空白、字符、补丁内容和文件集合敏感；只消除操作系统换行表示的差异。
- 合成基准准备器、真实任务检出器和真实实验器的 Git 子进程统一附加
  `-c core.longpaths=true`。本版尚未覆盖 Runner 自身的二次 clone 与工具层 Git 命令，
  该遗漏由 V0.5.2 补齐。
- 该 Git 配置只作用于当前命令，不修改开发机或 CI 账号的系统、全局配置。
- 增加 LF/CRLF 等价、清单字段冲突、目录逃逸、补丁改名与危险路径、空任务目录和覆盖保护
  等测试，提高 CI 覆盖率余量。

## 验收结果

- `168 passed`
- 总覆盖率 `90.74%`，高于 90% 门槛
- `ruff check .` 通过
- `python -m compileall -q src tests` 通过
- `git diff --check` 通过

本版只做跨平台发布修复，没有调用 DeepSeek、没有产生新 Token 或费用，也没有改写
`v0.5.0` 的真实 Issue 预筛选结论。`v0.5.0` 标签保持不可变，修复以 `v0.5.1` 发布。
GitHub Actions 随后证明工具层仍有长路径遗漏，因此 `v0.5.1` 也保持不可变，并由
`v0.5.2` 继续修复。
