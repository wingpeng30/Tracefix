# V0.7.1：验收口径校正与失败反馈收敛

## 目标

本次针对真实 Issue 预筛选暴露的两个高优先级风险收尾：

1. 不把 Agent 最后一次自行选择的 `run_tests` 误称为“公开测试通过”；
2. 让模型在无效补丁或截断搜索结果后得到可执行的下一步，而不是重复同类调用。

这不是新的检索或压缩算法，也不宣称准确率提升。它的作用是让后续 Token 效率实验的成功标准可信、失败轨迹可诊断。

## 实现内容

### 1. 分离三种运行结果

`RealTrialResult` 现在分别记录：

- `agent_completed`：模型是否正常给出最终回答；
- `agent_selected_tests_passed`：模型自行选择的最后一次测试是否通过；
- `public_tests_passed`：Agent 可见、任务专属公开测试是否通过；
- `independent_tests_passed`：评测端注入 Agent 不可见 `test.patch` 后的验收是否通过；
- `source_patch_applied`：Agent 产生的补丁能否应用到固定源码提交；
- `tests_modified`：Agent 是否修改测试文件。

当前三个 SWE-bench 风格真实任务没有独立的 Agent 可见任务专属公开测试，因此
`public_tests_passed` 明确写为 `null`。它不能再从 `agent_selected_tests_passed` 推断。
`resolved` 只有在 Agent 正常完成、补丁可应用、隐藏验收通过且未修改测试时才为真。

### 2. 改善模型可恢复反馈

- `apply_patch` 返回“补丁没有改变文件”或“已经应用”时，Agent 仅追加一次中文恢复提示，要求
  先读目标文件和 Diff，再形成实际修改；
- 搜索结果因展示上限被截断时，模型可见投影中附带 `next_action`，明确建议用具体路径、glob
  或关键词缩小范围；
- Repository Indexer 在 `ast.parse` 期间局部抑制 `SyntaxWarning`，避免 Pylint 的故意非法
  转义测试夹具淹没实验控制台。真正的 `SyntaxError` 仍按原逻辑记录并跳过。

2026-09-13 启动 Pylint 任务的一次关闭 Token 优化运行：

- 产物：[prescreen-summary.json](D:/Tracefix/runs/real-prescreen-20260913T031806Z-8ee6ef59/prescreen-summary.json)

该运行仅有一题、一个组别，而且工作树尚未提交，不能用于比较 Token 优化效果。它只证明：
新的验收字段可将“中断、Agent 自选测试、隐藏验收、补丁可应用性”分开记录，且预算终止后仍保留完整轨迹和独立验收结果。
