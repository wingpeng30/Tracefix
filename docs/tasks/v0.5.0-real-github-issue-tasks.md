# V0.5.0：真实 GitHub Issue 任务集

## 任务目标

在 V0.4.0 合成多文件任务之外，引入一组真正来自公共 Python 仓库的任务。任务必须具有
实质不同的跨文件约束、固定上游提交、Agent 不可见的验收补丁和可审计来源，不能再靠重复
文本人为制造长上下文。

## 实际完成

- 新增 `RealIssueTask`、`RealTaskArtifactHashes`、`RealTaskValidation` 和
  `load_real_issue_tasks()`。
- 清单强制使用 canonical GitHub HTTPS URL、40 位 base/environment commit、至少两个 gold
  源码文件和至少一个隐藏测试文件。
- 加载时验证任务目录边界、符号链接逃逸、补丁路径、文件集合及三个 SHA-256。
- `prepare_checkout()` 在新目录克隆仓库并以 detached HEAD 检出固定 commit；不复用脏目录。
- `validate_checkout()` 联合执行 `git apply --check test.patch gold.patch`，验证隐藏测试与 gold
  补丁在同一 base 上兼容。
- `apply_hidden_tests()` 只提供评测结束后的隐藏补丁接入点，不应用 gold patch，也不运行测试。
- 新增 `tracefix validate-real-tasks` CLI，默认离线校验；`--with-checkout` 才访问网络。
- 根包公开导出新接口，开发版本提升到 `0.5.0`。

任务选择为 pytest #8399、Pylint #8898 和 Sphinx #9461。gold patch 分别涉及 2、3、3 个源码
文件，修复约束分布在不同实现层，测试补丁又位于独立测试文件。上游源码按需克隆，没有
整份提交到 TraceFix。

## 安全与评测边界

Agent 运行时只应获得 `problem.md` 和 base checkout。gold/test patch 留在任务目录，未来真实
评测器必须确保它们不进入 Agent 工具根目录、消息或轨迹。清单中的 Issue 文本是去除模板
噪声后的节选，并显式标记 `curated_excerpt`；gold/test patch 保留数据集版本。

本机没有 Docker，因此本轮没有安装三个历史项目的依赖，也没有运行官方 FAIL_TO_PASS 和
PASS_TO_PASS。当前结论仅是：三个固定 commit 均可从 GitHub 获取，文件摘要正确，隐藏测试
和开发者补丁能够联合通过 Git 预检。不能把它表述成“TraceFix 解决了三个 SWE-bench 任务”。

## 验证结果

- 3/3 清单离线哈希与补丁文件集合通过。
- 3/3 上游 base commit 精确检出。
- 3/3 `test.patch + gold.patch` 联合 `git apply --check` 通过。
- 完整自动化验收：`145 passed`，总覆盖率 `91.04%`（门槛 90%）。
- `ruff check .` 与 `python -m compileall -q src tests` 通过。
- 模型调用 0 次，费用 `$0 / ¥0`。
