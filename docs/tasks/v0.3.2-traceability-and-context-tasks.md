# V0.3.2 任务说明：可追溯运行与语义型多文件任务

## 目标与完成内容

本次解决两个问题：以前的结果只记录待修仓库 commit，无法确认运行的是哪一版 TraceFix；
旧长上下文题又主要靠重复生成文本制造长度，不能证明压缩保留了有用事实。

实现内容：

1. 新增 `RunProvenance`，每次运行记录 TraceFix `version`、Git commit、未提交修改状态、任务
   SHA-256、模型参数、Python/平台和 Pydantic、LiteLLM、python-dotenv 版本。
2. 溯源清单进入 `result.json` 和轨迹的 `run_provenance` 事件。没有 `.git` 的安装包明确记录
   `null`，不会把外层仓库误认为 TraceFix，也不会阻断运行。
3. 新增默认关闭的 `--record-request-views`。开启后，每次模型调用前写入脱敏的
   `model_request_view`，内容就是 `ContextManager.prepare()` 产生的实际消息视图与工具定义。
4. 脱敏器除 `sk-` 模式和敏感字段名外，也替换当前进程中敏感环境变量的实际值。
5. `BenchmarkTask` 新增 `hidden_tests_dir`。隐藏测试不复制到 Agent 源仓库，只在最终独立
   评测时注入；`verification_kind` 明确区分公开测试与“公开 + 隐藏”判定。
6. 新增四道静态、多文件任务：

   - `config_precedence`：四层优先级、显式 `False/0` 和空白环境变量；
   - `event_merge`：规范化身份、时间/序列冲突、payload 合并和首次出现顺序；
   - `retry_pipeline`：永久/瞬时错误分类、重试预算与 1-based 退避；
   - `shipping_route`：区域、重量边界、温控资格和多级稳定排序。

每题的关键规则分散在至少三个实现模块，公开测试只暴露部分症状，隐藏测试覆盖容易被遗漏的
约束。任务没有生成重复段落，也没有强制读取顺序或范围，Agent 需要自己选择搜索和读取行为。

## 公共接口与兼容性

- 新公共类型：`RunProvenance`、`collect_run_provenance()`、`task_sha256()`。
- 新轨迹事件：`run_provenance`、`model_request_view`。
- `AgentConfig.record_request_views` 默认 `false`，所以旧命令不会产生额外大轨迹。
- `RunResult.provenance` 是必填结果字段；由 `TraceFixRunner` 自动生成。
- 已有不声明 `hidden_tests_dir` 的 12 道任务行为不变。
- 包版本由 `0.3.1` 升至 `0.3.2`。

## 安全与非目标

实际请求视图仍可能包含项目自身的业务代码，因此它是“凭据脱敏”而不是“公开发布安全”。
轨迹仍默认只留在被 Git 忽略的 `runs/`。本版没有调用真实 API，没有声称四道任务已被模型
解决，也没有把隐藏测试反馈给 Agent；这些任务用于下一阶段压缩 A/B。

- Ruff 与 compileall：通过；
- 四道新任务：初始失败 4/4，gold patch 应用成功 4/4，公开 + 隐藏测试通过 4/4；
- 真实 API：未调用，费用为 0。
