# V0.8.2：节省空间的环境准备与可信验收

## 目标

本版把真实 SWE-bench 候选的“能检出、补丁能应用”推进为可审计的离线行为资格验证，同时不让
TraceFix 为每道题重复下载 Python 或无边界占用磁盘。本轮未调用 LLM、未改写历史实验，也未推送
远程。

## 实现

- 新增版本化 `EnvironmentRecipe`。每题可声明兼容 Python 小版本、额外依赖、无 Shell 构建步骤、
  经过说明的选择器替代、支持平台及源码导入探针；配方 SHA-256 进入环境身份。
- `prepare-real-environments` 会盘点 Python Launcher、当前 Conda、Conda `envs/` 目录及已登记的
  TraceFix 解释器，读取真实版本后优先复用。首批 Pylint 使用本机 Python 3.10，Requests 使用
  Python 3.9，pytest 使用 Python 3.12；没有自动安装新的大版本。
- 环境复用同时要求任务 ID、固定 commit、镜像、配方哈希和解释器版本一致，并以健康标记保护。
  项目不会以 editable 方式安装固定源码；base/gold 在各自独立 Git 副本中测试。
- 新增 `inspect-real-environments`、`clean-real-artifacts`。清理默认只预览；`--apply` 只会删除
  含 `.tracefix-environment.json` 或 `.tracefix-workspace.json` 标记且位于指定根目录内的目录。
- 默认在创建新环境前检查剩余空间是否至少 10 GiB；空间不足、解释器缺失、依赖失败和平台不支持
  均写为结构化状态，不伪装为测试失败。
- 行为验收先执行 `--collect-only` 核对官方选择器，再运行 JUnit；base 必须是断言失败、gold 必须
  在同一集合通过。构建使用副本内临时目录，并记录诊断；源码导入探针要求模块实际来自当前
  base/gold 副本，而不是 site-packages。

## 使用方式

```powershell
# 先观察解释器和 TraceFix 自己登记的磁盘占用
.\.venv\Scripts\python.exe -m tracefix.cli inspect-real-environments `
  --environment-root runs/real-candidate-test-envs-v082b

# 自动选择本机兼容解释器；统一使用清华 PyPI 镜像
.\.venv\Scripts\python.exe -m tracefix.cli prepare-real-environments `
  --tasks benchmarks/real_candidates `
  --source-root runs/real-candidate-validation-v080b `
  --test-env-root runs/real-candidate-test-envs-v082b `
  --recipes benchmarks/real_recipes

# 只预览可回收项；确认后才加 --apply
.\.venv\Scripts\python.exe -m tracefix.cli clean-real-artifacts `
  --environment-root runs/real-candidate-test-envs-v082b
```

## 验证与限制

新增测试覆盖配方变更使复用失效、未登记目录不会被算作可清理空间、缺少选择器说明被拒绝，以及
base/gold 导入路径隔离。本版相关的环境、行为与 CLI 回归为 **29 passed（27.06 秒）**；Ruff、
compileall 和 `git diff --check` 通过。完整覆盖率命令在当前 Codex Windows 受限会话运行到
`test_benchmark.py` 后出现未退出的 Python 子进程，已中止，因而本轮不把“完整 205 项覆盖率”
宣传为已验证结果；该基础设施现象应在用户本机终端单独复查。真实验收结果见
[`v0.8.2-real-environment-validation.md`](../experiments/v0.8.2-real-environment-validation.md)。

本版不下载任意 Python 版本；仅在本机找不到配方要求的版本且 Conda 可用时，才会创建一个
`runs/<root>/.tracefix-interpreters/` 下的项目专用解释器。Docker/Linux 验证和官方完整
PASS_TO_PASS 仍是后续工作。
