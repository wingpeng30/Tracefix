# V0.7.2：真实任务预算调整与 200k 预筛选

## 为什么调整预算

此前 Pylint 的 120k 试运行连续在约 122k 至 131k 的累计输入处中断，通常尚未运行测试。
这说明 120k 对当前真实中型仓库是低成本冒烟上限，而不是适合判断 Agent 能否完成修复的预算。

本次将**仅真实任务命令**的默认累计输入预算调整为 350,000 Token：

- `real-prescreen`
- `real-repo-map-prescreen`
- `real-paired-eval`

普通 `run`、`eval` 仍默认 80,000 Token，避免日常调试被无意放大成本。`--max-input-tokens`
和 `TRACEFIX_MAX_INPUT_TOKENS` 仍可覆盖默认值。200k 是跨轮累计用量上限；单次请求的
32k 历史折叠阈值和模型上下文硬上限均没有改变。

## 实现与验证

- `_resolve_shared(..., real_issue_budget=True)` 为真实任务命令传入 350k 默认值；
- 添加 CLI 回归测试，确保真实预筛选为 350k、普通评测仍保持 80k；
- `tests/test_cli.py`：14 passed；Ruff 和 `compileall` 通过。

## 真实预筛选

下列记录是在本次默认值继续提高到 350k 前，以显式 200k 上限执行的；它证明 120k 过短。
后续真实任务默认值已是 350k。命令在固定源码副本、独立测试环境和开启 Token 优化的条件下执行：

```powershell
tracefix real-prescreen `
  --tasks benchmarks/real_tasks `
  --source-root runs/real-task-validation `
  --test-env-root runs/real-task-envs-v2 `
  --max-steps 24 --max-test-runs 6 `
  --wall-time-seconds 900 --context-trigger-tokens 32000
```

完整结果：[prescreen-summary.json](D:/Tracefix/runs/real-prescreen-20260913T033456Z-55f3c394/prescreen-summary.json)。

## 结果解释与决策

提高预算是必要的：pytest 和 Sphinx 已能自然完成，不再像 120k 冒烟期那样普遍被累计预算截断。
但它**没有**使这些任务成为上下文压缩实验样本：三题最大单次请求仍未达到 32k，历史折叠次数都为 0。
此外，三题都未满足“至少五个有业务意义文件被读取”的预筛选门槛；Pylint 还没有形成测试—补丁反馈闭环。

因此不能启动 `real-paired-eval`：它需要至少三道已入选任务。下一步不是对这三题重复花费 API
费用，而是建立真正会自然积累跨文件证据和测试反馈的长轨迹任务集，并先以单次请求视图确认折叠触发。
