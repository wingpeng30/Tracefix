# V0.8.0：真实候选池与离线结构筛选

本版新增 `real_candidates` 模块与两个 CLI 入口：

```powershell
tracefix collect-real-candidates --revision <固定 revision>
tracefix screen-real-candidates --tasks benchmarks/real_tasks --source-root runs/real-task-validation
```

收集器支持 Hugging Face `datasets` 的固定 revision，也支持本地 JSON/JSONL fixture。它按 pytest、Pylint、Sphinx、Requests 四个仓库各 3 题建立候选配额，解析 gold/test patch 路径、计算 SHA-256，并将问题与补丁工件保存到候选目录。候选池 JSON 只保存结构信息和排除原因，不保存模型响应。

结构筛选入口复用现有 `RepositoryIndexer` 和 `RetrievalEvaluator`，输出索引规模、符号数量、Repo Map 候选和 Hit@1/3/5、Recall@1/3/5、MRR。它不调用 LLM，也不将离线定位指标解释为修复成功率。

本机验证：新增候选收集/本地 fixture 测试与 CLI 回归共 16 项通过；Ruff 和 compileall 通过。对现有三道真实任务运行的离线结果仍为 Repo Map Hit@1 66.7%、Hit@5 100%、MRR 0.833。

当前收集器输出的是候选工件和结构记录；固定源码克隆、Python 测试环境和 base/gold 行为验证仍通过既有 `validate-real-tasks --with-checkout` 与 `validate-real-behavior` 分阶段完成。只有验证通过的任务才进入后续 350k 真实 LLM 预筛选。
