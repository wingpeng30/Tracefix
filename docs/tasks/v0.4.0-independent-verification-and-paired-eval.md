# V0.4.0 任务说明：独立验收与配对重复实验

## 完成内容

`BenchmarkTaskResult` 不再用一个 pytest 退出码代表全部成功，而是分别保存：

- `agent_completed`：Agent 是否以 `COMPLETED` 正常结束；
- `public_tests_passed`：任务仓库内公开测试是否通过；
- `independent_tests_passed`：Agent 完成后才注入的隐藏测试是否通过；
- `tests_modified` / `changed_test_files`：测试文件或 pytest 发现配置是否有净修改。

新的 `resolved` 要求 Agent 正常结束、公开测试通过、没有修改测试；存在隐藏验收时还必须隐藏
测试通过。公开测试和隐藏测试使用两个独立 subprocess，不再把二者合成一个退出码。兼容字段
`verification` 暂时保留，并明确指向公开测试结果。

新增 `PairedExperimentRunner` 与 `tracefix paired-eval`：每题每组至少重复三次，奇数轮按
关闭压缩→32k 压缩、偶数轮反向运行。模型、任务、预算、汇率和代码版本保持一致，实验组
只覆盖上下文开关与 32k 阈值，并强制保存脱敏请求视图。

轨迹分析器确定性统计：

- 同一路径第二次及以后的 `read_file`（文件重读）；
- 工具名与参数完全相同的再次调用；
- 工具失败；
- 工具结果首尾裁剪事件；
- `batches_compacted > 0` 的真实历史折叠；
- 首次真实折叠之后的工具失败和最终未解决 trial。

这里把“压缩后错误决策”限定为可复核代理指标：折叠后的失败工具调用，或发生折叠后最终
未通过独立验收。它不读取或臆测模型隐藏思考。

## 设计边界

隐藏测试仍属于本仓库维护的合成任务答案，Agent 运行期间不可见，但不是安全意义上的远程
保密服务。测试修改检测基于最终 Git Diff；如果 Agent 修改后完全恢复，不计为篡改。原始
配对实验产物保存在被忽略的 `runs/`，对外只提交脱敏聚合数据与结论。
