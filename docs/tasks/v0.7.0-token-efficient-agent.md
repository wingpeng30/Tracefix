# V0.7.0：面向 Token 效率的行动策略与工具结果投影

## 目标

TraceFix 的核心目标调整为：在相同模型、任务、Git commit 和预算下，尽量减少输入 Token 与等待时间，同时不降低独立验收通过率。本版不声明任何效果提升；它先把策略、审计和可重复对照做成可测基础设施。

## 本次实现

- `AgentConfig.token_optimization_enabled`：默认开启；关闭时禁用工具结果精简、只读缓存和行动引导，作为同预算对照组。
- `ToolResultPresenter`：完整 `ToolResult` 继续写入 `tool_returned` JSONL 事件；只有模型可见的 tool message 被确定性投影。搜索最多保留 6 条匹配；读取、测试输出和 Diff 保留首尾及明确裁剪标记。
- 缓存安全性：重复 `search_code` / `read_file` 只有在首次完整结果仍位于当前模型请求视图中才返回引用；若历史压缩已隐藏该结果，就重新执行读取。`apply_patch` 和 `run_tests` 后都会清空只读缓存。
- 预算策略：累计输入达到 85% 时拒绝宽泛探索，但保留一次具体文件或受限 glob 的定向读取，而不是阻断关键证据。
- 行动引导：读取 Repo Map 候选文件不再强制进入 PATCH 阶段；仅提供软提示，模型仍可根据失败测试补读调用方。
- 可观测性：`AgentState` / `RunResult` 新增模型请求、工具执行、上下文准备、仓库索引耗时，以及搜索、读取与缓存调用数；轨迹新增 `tool_result_presented`，可核对原始和模型可见字符数。

## 公平对照方法

同一题至少运行三次，交替顺序为 C/T、T/C、C/T：

```powershell
# C：对照组，仍保持同样的 Repo Map、上下文窗口、模型与预算
tracefix run --repo <repo> --task-file <task.md> --no-token-optimization --record-request-views

# T：Token 优化处理组
tracefix run --repo <repo> --task-file <task.md> --record-request-views
```

比较独立验收通过率、输入/输出 Token、美元/人民币估算成本、总耗时、模型请求耗时、工具耗时、重复读取和缓存命中。不得只比较成功样本，也不得把本地“约四字符一 Token”估计替代供应商 usage。
