# 上下文管理

TraceFix 将完整审计历史和发给模型的请求视图分开保存。`MessageHistory` 与 JSONL 轨迹保留原始消息；
`ContextSessionState` 保存投影版本、历史水位、请求前缀哈希、工具 schema 哈希、压缩代次和 tokenizer
身份。检查点恢复时会核对这些身份；状态损坏、历史前缀漂移或工具定义变化会阻止继续。

## 消息顺序与缓存

启动系统指令和首次用户任务构成固定前缀。后续用户指令、普通提醒、Skills、测试事实、源码变更后的
证据失效通知和工具响应都按原有角色追加到尾部。动态 `system` 消息不会仅因角色而移动到开头。
多工具调用及其结果作为完整批次处理；尚未闭合的工具批次不能压缩或检查点保存。

用户消息保持原文、角色和顺序。摘要只描述较早的完整工具轮次，不替换用户要求。压缩时保留用户消息、
已激活 Skills、最新验证事实和最新测试证据；无法在目标容量内安全压缩时保留最小安全内容，并在最终
请求视图仍超出有效输入容量时拒绝发送。

工具结果缓存只在模型完整看到该结果、该结果未被上下文裁剪且源码身份未变化时返回引用。部分读取、
搜索截断结果、被压缩结果或已失效源码的结果都会重新读取；旧请求已经发送后不会被追溯改写。

## 窗口与压缩

默认模型窗口为 1,000,000 Token。有效输入容量按下式计算：

```text
有效输入容量 = max(0, 模型窗口 - max(上下文输出预留, 单次输出上限) - ceil(模型窗口 × 1%))
默认触发阈值 = 有效输入容量 × 80%
默认压缩目标 = 有效输入容量 × 60%
```

显式 `context_trigger_tokens` 覆盖 80% 比例阈值，但会被限制在有效输入容量以内；兼容字段
`context_retain_ratio` 在同时设置显式绝对阈值时，定义压缩后相对该阈值的目标比例。压缩以完整
工具批次为单位。一次压缩提交一个新投影和递增代次；后续请求复用该投影，只拼接新的原始消息，直到
下一次触发。达到阈值但没有可安全删除内容时，只对同一历史水位记录一次 no-op，不重复生成相同摘要。

计数优先使用完整消息和工具 schema 的供应商模板。DeepSeek V4.1 tokenizer 身份固定为官方
`deepseek-recipe==0.1.1` 及经过 SHA-256 校验的 tokenizer 文件。该计数标记为 `estimate`，不作为
正式费用预算或供应商硬窗口上界。请求计数不可用时使用 TraceFix 本地 JSON 估算，并记录具体方法；
已固定身份的 tokenizer 丢失、哈希变化或检查点身份不符时拒绝恢复/继续。计数缓存绑定完整请求内容哈希
与 tokenizer 身份，工具 schema 在一次请求中随消息一同计数。

单次输出预留至少覆盖请求的最大输出 Token；若 `context_output_reserve_tokens` 更大，则使用更大的
预留值。压缩策略不改变累计 Token、请求次数、测试次数或费用预算。供应商返回的真实 usage 仍是实际
账单与累计预算的依据。

## 统一请求网关与计数复用

LiteLLMAdapter 通过 LLMGateway 准备请求。网关用同一份供应商参数分别计算两种输入数字：InputBound
保留 verified_exact、verified_upper_bound、estimate 和 unavailable 的原始资格状态；保守输入上界
继续服务既有费用预留公式。两者一起缓存，因此 ContextManager 先检查窗口、预算适配器随后做费用准入时，
同一消息和工具定义不会再次编码。若上下文裁剪或工具定义变化，正文身份随之变化，会重新计数；只有收紧
max_tokens 不影响输入计数，可以复用该结果。

缓存最多保存当前适配器运行内的128条结果，只记录正文 SHA-256、计数器身份、计数状态和数字，不保存消息
正文，也不写进检查点。正文身份绑定模型、供应商端点、消息、工具、thinking 设置、tokenizer 和编码规则；
最终请求则另行序列化并冻结，哈希覆盖真实发送的全部参数，包括输出上限、超时和重试值。冻结后适配器发送
这份请求，不能再从可变配置重新拼装一份。发送前同时核对完整请求哈希和计数所绑定的正文哈希，避免外层
请求哈希更新后正文被替换。模型、端点或计数器身份在运行中漂移会拒绝继续；消息或工具内容
改变则必须重新计数。恢复运行会创建新网关，不复用上次进程的缓存。

常规模型若没有可用本地计数器，计数状态会保留为 unavailable。普通未预算调用可继续发送，但没有保守
输入上界的费用预算路径会拒绝准入；正式 P2 只接受完成资格确认的精确计数或可验证上界，不把估计冒充资格。
供应商调用开始前发生的计数、身份或预算失败属于未发送；供应商响应超时或用量缺失仍保留未知状态和费用预留，
不自动重放。

正式对照实验使用 comparison_counter.py --serve 启动 JSON Lines tokenizer worker。OfficialCounter 在一次
任务运行内惰性启动、串行复用它；单次计数限时120秒，批量计数限时1800秒，两个期限都覆盖写入和等待响应。
worker 启动时完整核验固定依赖和 tokenizer 文件、加载编码器并回报身份，
请求前再核对文件大小和修改时间。客户端核对协议版本、请求 ID、身份和结果数量。超时、EOF、坏响应或身份
变化会关闭 worker 并把它标记为失败，不重启、不重发。Runner 在运行结束时关闭自己创建的网关；进程恢复时
worker 会重新启动并与协议中固定的身份比较。读取缓存、网关计数缓存和供应商前缀缓存是三种独立机制，互不
替代。

实现位于 [gateway.py](../src/tracefix/models/gateway.py)、[litellm_adapter.py](../src/tracefix/models/litellm_adapter.py)
和 [comparison_counter.py](../src/tracefix/comparison_counter.py)。当前工作区已完成定向离线回归；本机未配置
deepseek-recipe 和固定 tokenizer 文件，因此未运行真实 tokenizer 子进程或供应商请求，也没有正式发布验收结论。

## 自动与主动入口

压缩默认自动启用。`--context-agent-tool` 或 TOML `context_agent_tool_enabled = true` 会向 Agent 暴露
`compact_context(reason)` 工具；此工具只安排压缩，在当前工具批次闭合后才执行。它默认关闭，以免给已有
固定 B/C 对照组增加工具 schema。

运行期间可检查或主动压缩：

```powershell
tracefix context inspect --run runs\<run-id>
tracefix context compact --run runs\<run-id>
```

主动命令取得进程锁，只接受安全暂停或等待用户输入的会话；未决模型请求、工具结果、不完整批次、损坏
检查点或身份不匹配都会阻止操作。`compact_context()` 与 `inspect_context()` 的 Python API 使用相同
检查规则；交互聊天支持 `/compact`。本地与 Docker 检查点同时保存投影和 tokenizer 身份，不更改已有
已提交的 Docker 工具批次序号。

报告区分压缩提交次数、投影复用次数、no-op、唯一裁剪工具结果、计数方式及 tokenizer 身份。
