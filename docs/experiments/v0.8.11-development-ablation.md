## 失败分类与机制证据

独立验收原因：48 通过、35 pytest 执行失败、12 收集失败、24 空补丁、1 测试/配置修改拒绝。
最后一项为源码加测试修改。Agent 终止原因另列：44 自行结束、50 单项 Token 预算停止、14 步骤上限、
12 Agent 测试上限。终止原因不等于修复结论；资源停止后的补丁仍被独立验收。旧批次 32 项测试修改
拒绝与本轮 1 项不可直接用于因果比较，因为旧提示契约不同；旧基线也不合并到本轮。

行动优化组 30 项共有 603 条工具输出实际缩短、0 条变长，原始 1,405,221 字符变为 919,967 字符，
差额 485,254 字符。该组合还包含行动引导和读取缓存，因此不能称为“纯工具精简”的效果。字符差和
本地估算 Token 都不是供应商 Token 节省。Repo Map 在 30/30 项试次的运行结果中有记录，360 个候选累计 55 次
被读取；这些是机制观察，不能单独证明定位改善或修复收益。

上下文管理分两阶段：先裁剪工具结果，再依据裁剪后的本地估算检查 32k 历史折叠阈值。**历史折叠为
0 次，但工具裁剪在 18/30 项触发**。563 次请求准备的裁剪前峰值为 33,649，裁剪后峰值为 27,124，
没有达到历史折叠阈值。仅三次裁剪前过线：试次 49 步骤 17 为 32,592→26,066，试次 92 步骤 15/16
为 32,671→26,145、33,649→27,124。故不能将“峰值超过 32k 但未折叠”直接判为触发 bug。

累计工具裁剪计数为 417、重复请求视图的估算差额为 713,804；同一历史内容可能被重复计数，不能
冒充供应商实测节省，也不能写成整个上下文管理模块未激活。两道合成长上下文 fixture 的信息保留和
折叠验证仍独立引用 V0.8.9，不与本轮真实任务成功率合并。
