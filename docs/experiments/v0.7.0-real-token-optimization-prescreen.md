# V0.7.0：真实任务 Token 优化单次预筛选

## 实验范围

2026-09-13 对三个固定提交的真实任务各运行两次：一次关闭
`token_optimization_enabled`，一次开启。模型均为
`deepseek/deepseek-v4-flash`，累计输入预算为 80,000 Token，上下文折叠阈值为
32,000 Token，并保存实际模型请求视图。

任务为：

- `pylint-dev__pylint-8898`
- `pytest-dev__pytest-8399`
- `sphinx-doc__sphinx-9461`

原始结果位于 `runs/real-prescreen-20260913T021208Z-cf0fa879` 至
`runs/real-prescreen-20260913T022015Z-b4cc0415` 的六个运行目录。所有运行记录的
TraceFix commit 均为 `c4eecc0e06cf3956f1a98c14dd3750911a5d6ace`，但
`tracefix_worktree_dirty=true`，因此本组只能作为开发期预筛选，不能作为最终可复现实验。

## 逐题解释

### pylint-8898

关闭组与开启组都因累计输入 Token 超限中断。开启组将搜索从 12 次降为 7 次，并开始尝试补丁，但三次补丁包含重复函数、删除后又调整等错误，没有运行测试。输入 Token 仅从 87,389 降至 87,114，说明减少工具文本被额外两个模型步骤和较长输出抵消。本题当前主要问题是行动规划和补丁验证，而不是历史折叠。

### pytest-8399

开启组是唯一真正解决的运行：输入 Token 从 83,117 降至 56,110，步骤从 11 降至 9；只修改 `src/_pytest/unittest.py`，公开测试、独立验收均通过，Agent 正常完成。关闭组虽然也改对实现，但又修改了 `testing/test_unittest.py`，未能在预算内运行 Agent 测试，公开测试失败且 Agent 未完成。本题为 Token 优化有效的积极个案，但每组只有一次，尚不能排除模型随机性。

### sphinx-9461

两组都在累计 Token 超限前未运行测试。开启组少一次读取、少两次重复读取，并尝试一次补丁，但该补丁没有实际改变文件；输入 Token 基本持平（89,186 对 89,410），输出、费用和耗时反而增加。本题反映模型定位到相关模块后仍缺乏形成正确修改的证据与验证闭环。

## 为什么没有达到 32k 正式门槛

32k 阈值针对“单次模型请求视图”，不是多轮累计输入 Token。六次运行的最大单次请求估算只有 8,245～14,645 Token，因此历史折叠次数全部为 0。与此同时，多轮请求的累计输入可超过 80k，导致五次任务因 `token_budget_exceeded` 中断。这两项指标并不矛盾。

所有任务还都未读取至少五个有业务意义的文件；除开启优化的 pytest 运行外，也没有形成补丁—测试反馈闭环。因此它们不适合参加“关闭折叠 vs 32k 折叠”实验，但可以继续用于“关闭 Token 行动优化 vs 开启优化”的配对实验。

## SyntaxWarning 说明

Pylint 仓库中的这些文件是故意包含非法转义的测试夹具，用于验证 Pylint 对异常反斜杠和 Unicode 转义的诊断。TraceFix 的 Repository Indexer 使用当前 Python 3.12 对仓库文件执行 `ast.parse`，解析这些夹具时 Python 会输出 `SyntaxWarning`。它们不是 API、补丁或验收失败，也不会解释本次任务未解决。

后续可在索引器的 `ast.parse` 局部范围内捕获并忽略 `SyntaxWarning`，同时继续记录真正的 `SyntaxError` 跳过文件，减少控制台噪声；不应修改上游 Pylint 测试夹具。

## 结论与下一步

本组支持“工具结果精简与行动引导可能减少输入”的初步假设，但不能证明稳定提升：只有三题、每组一次、运行顺序未充分交替，且 TraceFix 工作区不是干净提交。下一步应先提交固定版本，然后针对这三题做每组至少三次的 C/T 交替实验。指标重点应是独立验收通过率、累计输入 Token、达到首个补丁/测试的步骤、无效搜索与测试修改率；不再把 32k 折叠触发作为这三题的入选条件。
