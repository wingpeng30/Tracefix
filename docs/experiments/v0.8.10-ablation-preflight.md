# V0.8.10 四组消融协议与零费用预检

本轮将既有消融草案接入执行器，冻结开发集的 120 个计划位置；不启动付费消融，也不运行留出集
Agent 评测。执行起点为 `f352e4b309ff43fe2bd564b421ff1cfbb5c47141`，本轮开发快照由原始协议中的
逐文件 SHA-256 和验证目录的快照固定；最终保存版本见本报告所在提交。

## 实验契约

既有 10 题是开发集，8 道普通资格作为主集合、2 道受审查收集失败资格单列。四组分别为全部关闭、
仅 Repo Map、仅行动优化组合、仅上下文管理（32k）。行动优化组合包含工具输出呈现、行动引导和
读取缓存，不能称为纯工具精简消融。每题每组三次，共 120 项；每轮按任务 ID 排序，各任务内将
四组顺序按 `(task_index + repetition - 1) mod 4` 左旋。旧默认两组 CLI 行为保留。

完整有效 Agent 配置、基础提示、评分契约哈希、任务/配方/源码哈希和日程见
[`frozen-protocol.json`](../../benchmarks/experiments/v0.8.10-ablation/frozen-protocol.json)。两组以外的
新增组也使用同一 Agent、严格验收、费用账本、恢复与证据分类入口。仅三个预定开关不同，预算仍为
输入 350k、输出 20k、24 步、6 次 Agent 测试、900 秒及单响应最多 4096 输出 Token。

选择规则在运行前写入 [`development-design.json`](../../benchmarks/experiments/v0.8.10-ablation/development-design.json)：
先对每题三次重复取均值，再按任务等权；只有主集合观察成功率不低于基线、平均输入与 Agent 时间均
下降且证据完整的配置可入选，依次按成功率、输入、时间和组名排序。无配置满足时保留基线，不强选
赢家；组合配置必须另做开发集验证。这是探索性规则，不能证明成功率非劣效。

## 复现入口

在项目根目录运行，首次执行的输出目录必须未存在；Windows 进程身份检查需要读取系统进程的权限。
第一条命令执行完整演练并内置一次恢复核验；第二条只读核验既有冻结预检，不重新执行模拟。如果第一条
中断且尚未生成完成的 `recovery-check.json`，使用 `--resume --execute` 并保留相同的 `--p1-evidence`
参数继续原实验。

```powershell
.venv/Scripts/python.exe scripts/ablation_preflight.py --output runs/ablation-reproduction-unique --pricing-evidence benchmarks/experiments/v0.8.10-ablation/price-evidence.json --p1-evidence runs/ablation-p1-recheck-20260922/behavior-validation-combined.json --execute
.venv/Scripts/python.exe scripts/ablation_preflight.py --output runs/ablation-reproduction-unique --pricing-evidence benchmarks/experiments/v0.8.10-ablation/price-evidence.json --p1-evidence runs/ablation-p1-recheck-20260922/behavior-validation-combined.json --resume
.venv/Scripts/python.exe scripts/ablation_formal_fixture.py --output runs/ablation-formal-fixture-unique
.venv/Scripts/tracefix.exe p2-summarize --experiment-dir runs/ablation-reproduction-unique/simulation
```

原始模型轨迹、服务进程路径与本机完整验证记录留在被 Git 忽略的 `runs/`。提交只包含源码、测试、
协议、脱敏锁与报告。后续顺序是先解决预算并执行开发集消融、冻结最终配置，再一次性评测 20 道
留出题；如果根据留出结果调参，必须标记污染，不能继续称为未使用的最终留出集。
