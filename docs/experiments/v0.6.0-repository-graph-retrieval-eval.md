# V0.6.0：Repository Graph 离线检索复评

## 改动

在首轮 Repo Map 离线评测发现 Sphinx 漏检后，索引器新增四项确定性能力：模块名到文件路径
反向索引、`from .x import y` 相对导入解析、符号名到定义文件反向索引，以及从关键词种子出发的
一跳 import/call 双向邻居扩展。每题最多保留 6 个图扩展文件，最终 Repo Map 仍限制在 12 个
候选，不调用 LLM。

所有任务描述、固定 base commit、gold patch 文件标签、关键词基线、候选上限与首轮实验一致；
唯一变化是图索引实现，因此可用于观察该改动的独立影响。

## 解释

三题中，Pylint、pytest 与 Sphinx 都至少有一个 gold 源码文件进入前 3/5 个候选，因此 Hit@5
达到 100%。但每题的首位仍不是 gold 目标：图扩展改善的是覆盖，不是种子排序；多文件任务的
Recall@5 也只达到 55.56%。样本只有三题，不能宣传为真实 Issue 总体解决率提升，更不能直接
推断 Agent 修复成功率提升。

下一步应保留当前图边，同时改善候选排序：区分源码、测试和示例目录；提高任务文本直接命中
路径/限定符号的权重；将图边按 import、调用、测试关联分别加权。离线 Hit@1 或 MRR 有稳定改善
后，再进行一次低成本 `--no-repo-map` / 默认 Repo Map 真实 Agent 预筛选。
