# V0.8.1：首批真实任务环境与行为验收

本实验对五道 SWE-bench Verified 候选执行固定 commit 检出、独立虚拟环境准备和
base/gold 双副本 pytest 验收。使用 Python 3.12.5、清华 PyPI 镜像与官方 `FAIL_TO_PASS`
选择器；未调用 LLM。

| 任务 | 环境 | base | gold | 资格结论 |
| --- | --- | --- | --- | --- |
| pylint-4551 | 可安装 | 旧 `wrapt` 与 Python 3.12 导入失败 | 同样失败 | 不合格 |
| pylint-4604 | 可安装 | 旧 `wrapt` 与 Python 3.12 导入失败 | 同样失败 | 不合格 |
| pylint-4661 | 可安装 | 旧 `wrapt` 与 Python 3.12 导入失败 | 缺少 `appdirs` | 不合格 |
| pytest-10051 | 可安装 | 缺少构建期 `_pytest._version` | 同样失败 | 不合格 |
| sphinx-10323 | 可安装 | 目标用例 xfail，退出码 0 | 目标用例 xpass，退出码 0 | 不合格 |

结果为 0/5 合格，因此不启动付费 LLM 预筛选。该结果说明环境“能安装”不能等同于任务
“可复现”：历史 Pylint 需要 Python 3.10 或更低版本；pytest 源码树需要在测试副本中完成
构建期版本文件生成；Sphinx 任务应改为使用能体现 base/gold 差异的独立验收入口。

原始本机结果位于 `runs/real-candidate-environment-preparation-v081b/` 与
`runs/real-candidate-behavior-validation-v081c/`。在 Windows Git 的 file-transport clone
受策略限制时，验收器改用 Git worktree 创建独立 base/gold 工作目录；这不共享工作树，补丁
和 `PYTHONPATH` 仍指向各自副本。下一个离线工作是增加任务级环境配方：
解释器版本、额外依赖和构建准备命令都必须固定后再重复验收。
