# V0.8.6：整体优化 C/T 实验协议与零费用演练

本文件固定 P2 的实验设计，不报告 Agent 修复成功率，也不包含任何付费模型调用。本轮代码基线为
`7995917ae1b27c76a62859883355db4e117647b8`；零费用演练产生的原始协议位于
`runs/p2-protocol-validation-final/p2-dry-run/p2-protocol.json`。

## 固定设计

P1 的 10 道行为合格任务全部入组。8 道普通断言失败任务是主分析集；Pylint-4551 与 4604 是受审查
收集失败任务，单列报告。Requests-1724 与 Sphinx-10323 不入组，原因保持 P1 的“未复现”和“待平台
验证”结论。

每题每组重复三次，共 60 次。任务 ID 固定排序；三轮依次为 C/T、T/C、C/T。C 同时关闭行动优化、Repo
Map 和上下文压缩；T 同时开启三者，压缩阈值为 32,000 Token。两组均固定为累计输入 350,000、输出
20,000 Token、24 步、6 次 Agent 测试、900 秒和每次输出 4,096 Token。

每次运行冻结 base commit、问题、gold/test patch 和环境配方哈希。Agent 结束后才把补丁应用到新的
base checkout，并注入独立测试；严格验收要求 JUnit、收集/执行审计、实际源码路径、完整 node ID 和前后
依赖指纹一致。空补丁、测试修改、补丁冲突、跳过/xfail/xpass、缺失证据或环境漂移都不计为解决。

调用。每次尝试使用独立目录，保留中断和基础设施失败证据，不覆盖既有结果。

汇总同时报告独立验收成功率、输入/输出 Token、Agent 与验收耗时、费用和终止原因；所有尝试计入分母。

### 最终审计结论

进一步读取 Agent 轨迹后确认，上述早期模拟仍存在空补丁，以及 Windows 未跟踪文件 diff 使用绝对路径的问题，
因此同样只保留为历史调查证据。修复后的唯一最终模拟目录为
`runs/p2-agent-simulation-final3-20260918/`，执行代码提交为 `91f0e0b84d654c9298d116413810df4f6e3bb1f6`。

- 60/60 个 Agent 补丁非空且在独立 checkout 成功应用；每项保存 `verification/<序号>/result.json`。
- 48 次常规任务产生完整 JUnit、收集/执行审计并按预期 assertion failure 分类；12 次 Pylint 特殊任务产生
  结构化 collection error。60/60 源码身份有效，依赖漂移为 0。
- 恢复运行复用 60/60，Agent 目录由 60 保持为 60；累计输入/输出各 120 Token，费用为 0。
- 正式入口与模拟入口共用排程、恢复和验收；费用账本在请求前预留，响应后按实际 Token 核算，任何不确定
  请求、费用帽不足或账本身份冲突都会停止，供应商隐式重试为 0。

最终门槛证据位于 `runs/p2-final-verification-20260918-v4/`：`260 passed in 176.89s`，语句覆盖率
`92.2625804010594%`、分支覆盖率 `81.41399416909621%`、综合覆盖率 `90.0270351456894%`；Ruff 与
compileall 通过。正式付费实验尚未启动，因为仓库中没有可审计的当前模型价格来源和总费用上限。

### 2026-09-18 启动门槛补强

协议以 P1 原始 `behavior-validation.json` 的 SHA-256、资格类型、base commit、依赖指纹和 gold 实际执行
node ID 固定入组身份；每次 `p2-check` 与运行均重验源码清洁度和环境指纹。Pylint-4551/4604 另在
`runs/p2-gate-p1-collection-audit-v2-20260918/` 重验：base 的唯一 collection ImportError 与配方匹配，gold
完整通过，新的审计没有阶段诊断。历史记录保留，但不再把旧的 collection-only execution-audit 诊断当作任务结果。

每个付费请求现在有稳定的试次/请求身份、预留和结算条目。未知请求、缺失或超限 Token、费用超预留和费用帽
不足都会停止实验。每个试次在 Agent 结果落盘后保存 `agent_completed`；恢复阶段仅验证该补丁，绝不自动重发。
这些改动未调用供应商，也不产生费用。
