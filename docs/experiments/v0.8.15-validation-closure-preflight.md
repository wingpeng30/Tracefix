# V0.8.15：Agent 测试反馈闭环与正式比较预检

本轮从 V0.8.14 结果继续，先修复 Agent 测试反馈，再准备同期 C/T 比较。**当前只完成工程实现、离线回归和价格/账本预核验；48 项付费实验尚未启动，20 道留出题未使用。** 本文不把工程改动直接解释为成功率提升。

V0.8.14 普通题同期基线是 C 12/24、工具呈现 T 12/24。轨迹审查发现 18 次 pytest 试次有 14 次未在 Agent checkout 执行冻结配方构建步骤；其中 28 次 Agent 测试调用因缺少 `_pytest._version` 无法提供有效反馈。另有真实补丁错误，因而环境修复只消除一个已证实障碍，不保证模型独立验收成功率会上升。历史 12/24 只作背景；新主要指标是新批次 8 道普通开发题的独立验收成功率。

## 实现与冻结方案

- 将冻结 `EnvironmentRecipe` 随 P2 配置传入 Agent runtime。在独立 Agent checkout 内运行允许的构建步骤，记录每步的命令、退出码、stdout/stderr 哈希、生成工件身份和目标模块实际导入路径。目标导入探针不匹配或构建失败时，在构造模型客户端之前停止。
- Agent 的 `run_tests` 统一使用配置的测试解释器、checkout 内 root/config/confcut 边界和独立临时目录，清除继承的 pytest 参数及插件注入，并保留已配置的仓库插件。只有收集审计、执行阶段、JUnit、pytest 退出状态和真实通过测试相符时才反馈“测试通过”；`--version`、只收集、空集合、全跳过/xfail 或不完整证据均不能触发通过。
- 试次结果保存 Agent 验证状态。启用闭环的 T 组在当前补丁未有有效测试通过证据，或尚未确认有非空代码改动时，不能直接把普通最终回复视作验证完成；修补会清除之前验证状态。C 组仍可按原控制策略运行。旧配置缺省关闭此策略，旧记录仍可读。
- 新设计固定 8 道普通开发题 × C/T × 每组 3 次，共 48 个位置；按三轮 C/T、T/C、C/T 排列。相同模型、基础提示、工具、任务、独立评分和预算；两组唯一差异是结束前的测试验证闭环。预算为每次输入 350k、输出 20k、24 步、最多 6 次 Agent 测试、900 秒、单请求最多 4096 输出 Token。2 道受审查收集失败资格题不进入此比较。
- 预注册采纳门槛：48 个位置均有有效证据、无未解决基础设施事故；T 独立验收至少 16/24，较同期 C 净增至少 4 次，至少 2 道题成功数净增。该门槛是实际改进目标，不是统计显著性保证。失败原因按独立验收和终止类别分别保留；未达标时保留基础配置。20 道冻结留出集保持未使用。

汇总实现也补正了验证闭环报告：处理组现在按 `validation_closure` 读取，而不会落入旧的上下文压缩组；不在 48 位置排程内的特殊资格任务计划数为 0；JSON 和中文报告都输出 16/24、净增与跨任务门槛。负例回归将 T 降至 15/24 后确认配置不会被采纳。
