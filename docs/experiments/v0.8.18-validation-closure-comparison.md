> **后续证据更正：** [V0.8.19 复盘](v0.8.19-validation-closure-failure-review.md)用共享审计发现第 19、39 项验收不可用，因此证据有效性为 46/48；本页有关“48/48 证据有效、无未决故障”的判断已被更正。固定分母下 C 16/24、T 13/24 的原始记录不变，T 仍未达到采纳线。请以 V0.8.19 的证据分类为准。

## 结果

2026-09-25 按冻结协议完成 48/48 项正式开发集比较。执行代码为 `97f521599f0602e79a50f782c4282001bbab6ed3`，使用 DeepSeek 官方直连别名 `deepseek-flash`；741 个响应事件均记录该模型身份。C 是全部优化和验证闭环关闭的基础 Agent，T 仅开启验证闭环。8 道普通开发题各组各 3 次，轮次按 C/T、T/C、C/T。20 道留出题未运行。

主要指标未改善：C 独立验收通过 **16/24（66.7%）**，T **13/24（54.2%）**，T 净少 3 次成功。配对结果为 12 对双方通过、7 对双方失败、4 对 C 通过而 T 失败、1 对 C 失败而 T 通过。只有 pytest-10051 一题净增（+1）；pytest-10081 净减 2，Requests-1766 与 Sphinx-10435 各净减 1。预注册采纳条件要求 T 至少 16/24、较 C 净增至少 4 次且至少两题净增，并要求证据完整、无未解决基础设施事故。成功数与净增条件均未满足，故不采纳 T，保留 C。

| 主集合结果 | C：基础 Agent | T：仅验证闭环 |
|---|---:|---:|
| 独立验收成功 | 16/24 | 13/24 |
| 输入 Token | 4,496,290 | 4,229,184 |
| 输出 Token | 63,998 | 63,505 |
| Agent 用时 | 1,632.33 秒 | 1,625.78 秒 |
| 账本计算费用 | ¥9.504564 | ¥8.966408 |

T 的输入总量比 C 低约 6.0%，输出低约 0.8%，Agent 用时低约 0.4%，计算费用低约 5.7%。这些次要指标不能抵消成功率下降，也不证明验证闭环带来了修复收益。8 题的小样本仅是开发集描述性比较，不构成显著性或泛化结论。

19 项 Agent 运行以单请求输入上界拒绝结束（C 11、T 8），没有请求发往供应商；这些原始 `benchmark_error` 均已核实为预算资源边界，不是网络或供应商故障。保存的补丁仍进入独立验收。C/T 的 19 项独立验收失败可见原因分别为：pytest 执行失败 6/7，空补丁 1/3，修改测试或 pytest 配置被拒 1/1。各组另有 Agent 自报“未验证”17/15 项；它与独立验收是不同证据，不按同一状态解释。没有未解决的基础设施事故。
