# V0.6.0：源码先验与种子排序离线复评

## 改动

在 Repository Graph 已将 Hit@5 提升至 100% 后，继续优化候选起点而不扩大图搜索范围：

- 对 `doc/`、`docs/`、示例、benchmark、`testing/` 和 `tests/` 目录施加源码候选降权；
- 任务文本出现完整模块名（如 `sphinx.ext.autodoc`）时，给予对应模块入口额外精确分；
- import、call 和测试关联边分别使用不同权重；测试边只影响相关测试选择，不抢占源码候选；
- 保持一跳图扩展、12 个候选文件和同一三道固定真实任务。

## 结论

该改动在固定三题离线样本中同时提升了 Hit@1 与 MRR，并保持图扩展带来的 Hit@5 覆盖；这是
进入小规模真实 Agent 预筛选前需要的证据。但样本只有三题，且指标只衡量 gold 修改文件定位，
不等于模型会读取、正确修改或验证这些文件。因此不能表述为真实 Issue 修复率提升。

下一步可以在相同三题上各运行一次 `--no-repo-map` 与默认 Repo Map 的真实 Agent 预筛选，
重点比较首个目标文件读取步骤、无关搜索/读取次数、补丁产生率、隐藏验收与 Token/人民币费用。
