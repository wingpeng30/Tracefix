# V0.8.7 P2 证据与评分契约

本轮只读取 `runs/p2-formal-deepseek-rerun-20260921/` 的既有 60 项工件，没有发起模型请求。
`p2-summarize` 与 `p2-diagnose` 现在共用版本 2 证据审计：逐项核对计划身份、运行结果、补丁、
验收 JSON 及其 SHA-256，并把运行终止、独立验收和基础设施事故作为三个独立维度。

统一统计确认 60/60 项证据有效：独立验收成功 15、失败 45；终止原因为 Agent 完成 24、步骤上限
12、测试上限 5、正常输入预算停止 17、单请求上界 1、基础设施事故 1。缺失或哈希不符的验收
工件现在记为 `evidence_invalid`，不会默认成 `passed`。主成功率仍使用全部计划位置作为固定分母。

## 提示与评分核对

评分契约 `p2-scoring-v1` 禁止新增、修改、删除或重命名测试、conftest、pytest 配置和
`setup.cfg`。同一规则生成 Agent 指令、严格验收路径分类和离线诊断；新协议保存契约版本和指令
哈希，C/T 使用相同评分说明。

旧 60 项实际请求没有这段完全一致的 P2 指令。通用提示允许“任务明确要求”时修改测试，而
pytest-dev__pytest-10356 的任务描述明确要求测试变更；它的 6 次运行中有 5 次因此触发测试修改拒绝。
其余测试修改只能确认是模型提交的可观察行为，现有证据不足以判断动机。旧分数保持不变。

32 个拒绝补丁经统一精确路径规则复核：28 个同时包含产品源码与测试，3 个只包含测试或探索文件，
1 个包含受保护配置。解析同时检查 diff 两侧路径，覆盖新增、删除和重命名；目录名只按完整路径段
判断，不使用任意子字符串匹配。

## 既有轨迹机制证据

T 组 662 条工具结果实际缩短，原始字符 1,580,658，呈现字符 1,019,280，净减少 561,378 字符；
没有结果变长。该字符差额是模型视图变化，不等同于供应商 Token 账单。C 组 703 条工具结果均未
改变。T 组 30 项均注入 Repo Map，共提供 360 个候选，52 个不同候选文件被实际读取。T/C 的失败
工具调用分别为 103/101，文件重读为 116/75。

两组上下文折叠均为 0。T 组最大折叠前上下文估算为 21,434 Token，C 组为 31,868 Token，均未越过
32k 阈值。因此已有数据只支持 Repo Map 与行动优化组合的激活事实及相关性，不支持任何单模块因果
效果，也不支持“压缩节省 Token”的表述。

## 后续实验冻结方案

既有 10 题固定为开发集。消融以全部关闭为基线，分别启用 Repo Map、行动优化组合和上下文管理；
行动优化组合明确包含工具结果呈现、行动提示和读取缓存。当前本地 12 道候选都已经过 P1/P2 查看，
不能改称留出集，距离目标 20 道新任务仍缺 20 道。

留出集按仓库分层并使用固定种子 `20260921`，在任何 Agent 运行前冻结；只依据 base/gold、环境和
证据资格筛选，不依据修复成败。长上下文机制验证使用预先构造或独立取得、在模型输出前已确定超过
32k 的任务，并与留出集效果估计分开。机器可读方案和统一诊断位于
`benchmarks/experiments/v0.8.7-p2-evidence-contract/`。
