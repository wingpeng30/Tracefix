# V0.5.0：真实 Issue 32k 触发预筛选

## 问题与预注册门槛

本实验不是比较“压缩开/关谁更好”，而是先判断三道真实任务是否有资格进入昂贵的配对
实验。每题只运行一次 32k 压缩组，且必须同时满足：至少一次完整历史折叠、最大单次请求
估算达到 32k、读取至少 5 个任务清单中的业务相关文件、出现补丁与测试反馈闭环、保存实际
模型请求视图。少于三题入选就停止，不运行 C/T 重复实验。

运行固定在 TraceFix commit `6a5537f5a169d62ffd8629101ed3e671cf59c13d`，开始时工作区
干净。模型为 `deepseek/deepseek-v4-flash`，temperature 0、关闭 thinking；每题预算为 24
步骤、240k 累计输入 Token、20k 输出 Token、15 分钟和 6 次测试。上下文软阈值 32k，
retain ratio 0.375。实际请求视图经过凭据脱敏后保存在本机轨迹。

## 结果

| 任务 | 状态 | 最大单次估算 | 历史折叠 | 有效读取 | 补丁/测试 | 隐藏验收 |
|---|---|---:|---:|---:|---:|---:|
| Pylint #8898 | 步骤耗尽 | 13,972 | 0 | 2/7 | 0/0 | 失败 |
| pytest #8399 | Token 耗尽 | 28,257（裁剪后 18,638） | 0 | 4/7 | 6/6 | 失败 |
| Sphinx #9461 | Token 耗尽 | 20,369 | 0 | 4/7 | 0/1 | 失败 |

合计输入 751,769 Token、输出 9,471 Token，费用 `$0.04610248`，按 7.20 汇率约
`¥0.33193786`。0/3 正常结束，0/3 通过独立隐藏验收，0/3 触发完整历史折叠。因此正式
配对实验没有启动，避免了 18 次无法回答压缩问题的模型调用。

这里“累计输入 Token 很高但单次上下文不到 32k”并不矛盾：累计值是 19～24 次模型请求
各自输入量的总和；折叠阈值判断的是某一次请求视图。pytest 的长测试输出发生了首尾裁剪，
24 次裁剪累计节省本地估算 79,367 Token，但 `batches_compacted` 始终为 0，不能把它记成
历史折叠。

## 失败归因

- Pylint 共 51 次工具调用，其中 45 次是搜索，最终没有读到足够的参数管理/初始化调用链，
  也没有生成补丁或运行测试。主要瓶颈是仓库定位，不是旧证据在压缩中丢失。
- Sphinx 读取 7 个文件但只有 4 个属于预先标注的相关文件，发生 5 次重读；唯一测试命令
  因包含 Shell 控制语法被安全层拒绝，之后直到 Token 耗尽仍未生成补丁。定位与工具规划
  都比摘要保真更早成为瓶颈。
- pytest 形成了 6 次补丁/测试循环，但修改了 `testing/test_unittest.py`，最终隐藏验收仍失败。
  这是 Patch Verifier 的真实信号，不过只出现在一题，优先级低于两题共同出现的定位问题。
- 三题精确重复调用都很少（合计 2 次）；此时加入简单的“完全相同调用去重”不会解决大量
  语义近似但参数不同的搜索，因此不作为下一主功能。

## 功能决策

下一主功能选择 **AST 符号索引 + 确定性 Repo Map**。理由是两题在预算耗尽前没有进入
补丁闭环，Pylint 尤其表现为 45 次搜索仍未建立跨文件关系。Repo Map 应先给出定义、导入、
调用方和测试映射，目标是减少无效搜索并提高 File Localization Hit@K。

第二优先级是 Patch Verifier：在检索版本稳定后，阻止修改测试、要求目标隐藏验收的代理
信号，并检查“测试通过但实现不完整”。当前证据不支持先改上下文摘要，因为没有任何任务
发生历史折叠，也就不存在“折叠后忘记早期规则”的观测。
