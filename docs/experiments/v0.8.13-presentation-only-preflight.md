原 V0.8.12 报告把 253 个 `context_compacted` 事件都算作历史折叠。现在按同一事件中的字段分别分类：`tool_results_pruned > 0` 计工具裁剪；`messages_compacted` 或 `batches_compacted` 大于零才计历史折叠；一个事件可以同时计入两类。关键字段缺失或互相矛盾时，记录证据问题，不用零值补齐。

用固定的一道合成任务跑通 P2 正常模拟 Agent 循环、工具调用、补丁落盘、独立 pytest 验收、汇总和恢复。该 fixture 产生 6 个位置（每组 3 次），6/6 通过独立验收，完成态恢复复用 6/6，没有追加模拟 Agent 实例。它不是完整的 60 位置真实任务演练；60 位置只在冻结协议中生成并校验。

工具结果中预置的目标源码路径、断言文本、异常类型和完整测试 node ID 均出现在模型可见视图中。长输出在三个处理组试次中触发了预期裁剪；重复读取缓存行为和预算终止恢复分别由独立回归覆盖。测试把真实供应商客户端构造替换为失败守卫，模拟闭环确认真实供应商客户端为 0、付费请求为 0。演练报告了 180 输入、36 输出 Token 和 0 虚拟费用；这些是测试桩数值，不是供应商 Token 或账单。

单一 fixture、预置修复补丁和 6 次通过只证明工程链路与目标标记可见，不说明模型真实修复成功率，不用于模块效果推断。原始试次、轨迹、临时 fixture 和 JUnit 留在本机 `runs/presentation-only-simulation-evidence-20260924/` 与 `runs/presentation-only-simulation-preflight-20260924-v2/`；脱敏摘要及工件哈希在 [`simulation-preflight.json`](../../benchmarks/experiments/v0.8.13-presentation-only-preflight/simulation-preflight.json)。
