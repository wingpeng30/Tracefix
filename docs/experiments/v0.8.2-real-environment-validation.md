# V0.8.2：真实候选环境与行为资格验收

## 实验边界

本记录是**离线环境与行为资格验证**，不是 Agent 修复实验：没有调用 DeepSeek、没有 Token、
费用或成功率数据。代码版本为 V0.8.2 开发工作树；候选来自固定的 SWE-bench Verified 工件，
源码来自 `benchmarks/real_candidates/` 所记录的 base commit。完整工作副本、安装日志和 JUnit
位于被忽略的 `runs/`，脱敏汇总见
[`benchmarks/experiments/v0.8.2-real-environment-validation.json`](../../benchmarks/experiments/v0.8.2-real-environment-validation.json)。

资格规则预先固定：相同、完整收集的目标 pytest 集合必须在 base 出现断言失败，且在 gold 通过；
依赖/构建错误、选择器不完整、xfail、跳过、超时、零测试和平台不支持都不合格。

## 环境盘点

本机发现已有 Python 3.9.21、3.10.20、3.11.16 与多个 3.12 解释器，因而未新建 Conda
解释器。已登记的本轮环境占约 125 MiB，运行盘剩余约 62.7 GiB，高于 10 GiB 门槛。Pylint
按配方使用 Python 3.10 + `appdirs==1.4.4`，Requests 使用 Python 3.9，pytest 使用 Python
3.12 并在每个 base/gold 副本运行构建步骤；Sphinx 配方明确标为 Linux-only。

因此合格任务为 **2/12**，少于“至少 3 题才启动付费预筛选”的门槛，正确行动是继续完善环境与
测试入口，而不是运行 Agent 或宣称真实修复效果。

pytest 三题在本次受限 Windows 自动化环境中，构建期 pip 临时目录遭到权限拒绝；V0.8.2 已把
构建临时目录限制为工作副本内并保留诊断，但该权限现象仍被严格归为 `build_error`。这是一条
环境兼容性证据，不能被当成业务 Bug 已复现。Sphinx 也没有通过删除上游 Windows xfail 来制造
结果。

## 启示与下一步

当前可用的两个任务不足以做 C/T 三次配对实验。下一步应先审查 pytest 的历史构建配方并在可控
环境复现，或在 Linux/容器中验证三道 Sphinx；同时保留未参与调参的候选作为留出集。只有至少
三题达到相同的 base/gold 资格规则后，才固定模型、预算、任务哈希和实验顺序，启动真实 Token
对照。
