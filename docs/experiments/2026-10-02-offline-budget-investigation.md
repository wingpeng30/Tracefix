## 真实工具验证与采用结论

两个注入录制客户端的真实 LiteLLMAdapter 场景均完成：宽范围裁剪→指定行补读→错误补丁→
缓存失效后新读取→回归门失败反馈→纠正补丁→独立 checkout 验收。
每个 Agent 消耗六个真实 pytest 进程；提前压缩场景有四次实际压缩。
usage 明确为模拟，原 source 不变，供应商请求为零。它证明控制流，不证明自主定位或成功率。

新增测试还覆盖同哈希不同运行、账本/配置篡改、残缺 JSONL、缺失响应/usage、工具未配对、
未执行返回、重复输出目录及供应商访问阻断。正式执行身份与产物哈希见本文后续记录。

**本批两个候选都不直接采用。下一批只优先修读取可见性契约。**
建议先做默认关闭的定向读取呈现：使用连续完整行页，明确源码身份、可见/遗漏范围和 cursor；
不静默裁剪、不返回模型无法解引用的缓存指针。保持现有 read_file 参数兼容，按已知任务、失败栈、
Repo Map 和查询选范围，不利用参考修复定位。先测真实载荷再决定是否启用。

验收要求：裁剪中间实现能通过 cursor 补全；补丁后旧 cursor/缓存失效；多工具配对完整；
压缩后的任务约束、最新修改与失败证据可追溯；真实 pytest 回归门及独立验证通过；成功对照
所需证据保留。在此基础上再考虑预算感知压缩，不能直接以更低阈值换取不可解释的证据丢失。
本批没有新的真实模型效果结论，也不申请或消耗新的付费额度。
