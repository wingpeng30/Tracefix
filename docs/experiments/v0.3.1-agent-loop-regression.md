# V0.3.1 Agent Loop 回归实验

本次实验使用与 V0.2.0 Baseline 相同的 10 个合成 Python Bug 和相同模型，验证 V0.3.1
针对补丁协议、重复失败和任务收尾的修复。脱敏数据见
[`benchmarks/experiments/v0.3.1-agent-loop-regression.json`](../../benchmarks/experiments/v0.3.1-agent-loop-regression.json)。

## 结果

| 指标 | V0.2.0 Baseline | V0.3.0 3k 压力实验 | V0.3.1 回归 |
| --- | ---: | ---: | ---: |
| Resolved | 10/10 | 7/10 | 10/10 |
| 正常完成 | 10 | 6 | 10 |
| 输入 Token | 184,730 | 203,390 | 110,060 |
| 输出 Token | 8,982 | 9,808 | 5,393 |
| 模型步骤 | 74 | 84 | 53 |
| 工具调用 | 87 | 101 | 66 |
| 完全重复调用 | 6 | 23 | 0 |
| 人民币估算费用 | ¥0.18140797 | ¥0.25072877 | ¥0.12353363 |

相较 V0.2.0，在解决率不变的情况下，输入 Token 降低 40.42%，模型步骤降低 28.38%，
工具调用降低 24.14%，费用降低 31.90%。

## 轨迹证据

- 模型在 10 个任务中都选择了 `*** Begin Patch`，10 次补丁均首次应用成功。
- 每个任务仅应用一次补丁、运行一次测试、检查一次非空 Diff。
- 10 个任务都收到 `ready_to_finish` 提示并正常返回最终回答。
- 没有工具失败、完全重复调用或补丁恢复提示。

这些证据说明 V0.3.1 解决了上一轮实际发生的补丁协议兼容和完成条件问题。Token 下降来自
轨迹缩短，而不是上下文压缩。

## 不能得出的结论

本轮虽然配置了 3k 软阈值，但单次请求视图均未达到阈值，压缩次数为零。因此本实验不能
证明上下文压缩有效。它应标记为 Agent Loop 回归实验，而不是压缩 A/B。模型存在随机性，
且 V0.3.1 同时更改了补丁格式支持、提示词和收尾信号，单次运行也不能估计各改动的独立贡献。

下一阶段需要使用同一已提交版本设计自然产生 32k 以上请求视图的长上下文任务，再分别关闭
压缩和启用 32k 压缩进行对照。
