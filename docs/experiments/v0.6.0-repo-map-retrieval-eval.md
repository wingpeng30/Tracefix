# V0.6.0：Repo Map 离线检索评测

## 目的与边界

本实验隔离评估“任务描述能否定位需要修改的源码文件”，不运行 Agent、不调用 LLM、不执行测试，
因此费用为 `$0 / ¥0`。三道样本是固定的 SWE-bench Verified 任务；每题的 base commit、任务
描述哈希和标准补丁均已在任务清单中固定。

`gold.patch` 仅在评测末端读取 diff header，以获得目标源码文件路径。补丁正文没有传入关键词
基线、Repository Indexer 或 Repo Map。基线只能看任务文本和文件路径；Repo Map 额外使用 AST
符号、导入名称和保守调用名称。两组均只取前 12 个非测试候选文件。

## 命令与产物

```powershell
.\.venv\Scripts\python.exe -W ignore::SyntaxWarning -m tracefix.cli retrieval-eval `
  --tasks benchmarks/real_tasks `
  --source-root runs/real-task-validation `
  --output-dir runs
```

上游历史源码在 AST 解析时可能含无效转义序列；`-W ignore::SyntaxWarning` 只抑制这些上游文件
警告，不改变索引内容。原始本机运行结果位于
`runs/retrieval-eval-20260911T044609Z-d5530a22/summary.json`，可提交的脱敏摘要见
[`../../benchmarks/experiments/v0.6.0-repo-map-retrieval-eval.json`](../../benchmarks/experiments/v0.6.0-repo-map-retrieval-eval.json)。

## 结果

| 指标 | 文件名关键词基线 | Repo Map |
| --- | ---: | ---: |
| Hit@1 | 33.33% | 0.00% |
| Hit@3 | 66.67% | 66.67% |
| Hit@5 | 66.67% | 66.67% |
| Recall@5 | 44.44% | 44.44% |
| MRR | 0.444 | 0.370 |
| 平均索引耗时 | — | 1,205.99 ms |
| 平均 Repo Map 大小 | — | 843.67 估算 Token |

按任务看，Repo Map 将 Pylint 从 Hit@5 `0/1` 提升到 `1/1`，并改善 pytest 的首个命中排名；
但在 Sphinx 上前 12 个候选没有任何 gold 目标，反而被简单文件名关键词基线领先。

## 结论与下一步

三题样本过小，且总体 Hit@5 打平、Hit@1 与 MRR 更低，**不能**把当前 Repo Map 宣传为有效
提升。它的价值是暴露了明确的工程缺口：当前相对导入没有解析到仓库模块，调用只保存为字符串，
图邻居扩展也依赖脆弱的名称拆分。

下一迭代应先实现模块到文件的反向索引、正确的相对导入解析、符号定义查找及有界 import/call
图扩展；然后用相同命令重跑本离线评测。只有离线定位指标稳定改善后，才值得支付真实 LLM 的
`--no-repo-map` 与默认 Repo Map 配对预筛选费用。
